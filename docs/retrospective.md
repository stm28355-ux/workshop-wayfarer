# Workshop Wayfarer 作りのふり返り（2026-11-27〜11-29）

11月27日から3日で、インクリメンタルRPG を作り、1.0.0 として公開した（工程0〜9）。勇者はオートランで止まらず進む。人は手元の3つの段（荷車・鍛冶場・修練場）で強さを作り、慣れた段から職人に任せていく。企画はその前に別のチャットで固めた（インクリメンタルRPG 構想メモ → 企画まとめ 11/27）。

Auto Battler・Arc-en-ciel Creator・Celestial Alchemy・Aether Atelier・Gateway Garden・Mythic Mosaic のふり返り（各リポジトリの `docs/retrospective.md`）の続きとして読む。

## 結論（先に3つ）

- **強さの予定表を先に作り、ボットで答え合わせしたのが最後まで効いた。** 第4回の立て直しで、地域ごとに「出るときのレベル・装備の格・技の比」を表にした（`tools/plan-balance.mjs`、`src/core/plan.js`）。敵とボスの数値は、その表どおりの勇者を戦わせて決めた（`r4-sim.mjs`）。工程9 は人に遊んでもらわず、地域4〜6 を続けて回すボット（`region-time.mjs`）だけで直せた。
- **人が遊んで確かめる回が多すぎて、途中で「テストだけで日が暮れる」と言われた（第18回）。** そこからは、決めたことと遊んだ感想を作った後の1枚の表にまとめた。後半の地域の確かめはやめ、釣り合いは道具で決めた。26回の判定表のうち、遊ぶ回は前半に偏っていた。
- **見た目（工程8）に判定5回かかった。原因は、動く絵と、文字が出たときの画面のずれだった。** 勇者の絵を2枚で切り替えたら「あり得ないほどチカチカ」した。「次の出発」や「敵の性質」の文字が出るたびに、下の段が動いた。止めた画面を測るだけでは見つからず、動かしながら見て初めて分かった。

- **決まりを純粋な関数にし、1刻み（0.1秒）で進めた。**

  - ボットは盤・鍛冶場・巻物の手に時間をかけ、地域1〜3 の通し（`run-through.mjs`）と地域4〜6 の通し（`region-time.mjs`）を数秒で回せた。
- **強さの予定表を、人の記録で直した。**
  - 第11回で、地域を出るときのレベル・格・技の比を決めた。
  - 第18回 G1 で、技の比を人の記録に合わせて大きくした（地域3 ×1.6 → ×3）。
  - 敵の数値は、予定の勇者で「入るときは負け、出るときは技の並びがあれば勝ち、なければ負け」になるように選んだ。

## 指示の出し方の評価

◎ とても良い　○ 良い（少し足すともっと良い）　△ 直すと良い

- ◎ **作り続ける理由がないことを、遊び手の目で一言に**（第3回）。「武器は1本強ければよく、作り続ける理由がない」。装備とバランスの予定を立て直すきっかけになり、格・加算・素材ごとの違いが生まれた。
- ◎ **余りのダメージの話**（第9回 B5）。「今の普通の攻撃は2回で2体倒せるが、斬り1回は1体しか倒せない」。数字の見落としを、例つきで示してくれた。
- ◎ **「テストだけで日が暮れる」「後半の地域でのチェックは不要」**（第18回）。進め方を変えるはっきりした指示だった。もっと早く（第10回ごろ）言ってもらえれば、遊ぶ回をさらに減らせた。AI から「何回遊ぶか」を先に聞くべきだった。
- ◎ **画面の並びを、オートランの考え方つきで**（第22回の一言）。「勇者の情報は左に、その隣に戦いの絵。オートラン系なので動いているシーンはあった方が良い」。「出口をマージの近くに。遠いので」。理由が書いてあり、そのまま作れた。
- ◎ **原因の当たりをつけた直し**（第25回）。「点滅しているのは勇者です」「HP の赤い棒の下の白いものは？ 一個前は出ていなかった」。AI が見つけられなかった所を、絞って教えてくれた。
- ○ **「地域選択は異常に見にくい」**（第24回）。AI はボタンの並びに変えたが、人は選び箱のまま白地にしてほしかった（第25回）。「見にくい」が「色」か「部品の形」かを確かめるべきだった。
- ◎ **画面が動く場面を具体的に**（第26回）。「次の出発が出た時、敵の性質が出た時に画面が動く。次の出発は地域の隣、敵の性質は敵の近くで良い」。場所まで決めてあり、一度で直った。
- ◎ **先へ進む判断を自分で**（第26回 Q5）。「修正は必要だが、この修正で直るので工程9に進んでも問題ないはず」。判定の回が1回減った。

## 人と AI の役割

- **人が強かったところ：**
  - 遊びの考え方（作り続ける理由・余りのダメージ・巻物はミスしてよい）
  - 気持ちよさ（歩く速さ・チカチカ・画面が動く）
  - ジャンルの見方（動く戦いの絵・地域選択・リタイア）
  - 進め方（遊ぶ回を減らす・先へ進む判断）
- **AI が強かったところ：**
  - 決まりの心臓部とテスト
  - 6種類のパズルの自動生成と確かめ
  - 鍛冶場の盤の探索、強さの予定表、通しのボット
  - ドット絵と背景、判定表と計画のメモ
- **AI が弱かったところ：**
  - 動く画面の見え方（点滅・ずれ）
  - 人の問いの読み違い（G4）
  - 遊ぶ回の数を先に決めること
  - ボットを最後の地域まで延ばすこと

## 次のゲームで使う手順

前作の29の手順に、今回の教訓を足した（30〜34）。1〜29 は Mythic Mosaic の `docs/retrospective.md` と同じ。

30. **（進め方）最初に「人が遊んで確かめる回」を決める。** 確かめるのは新しい遊びだけにし、釣り合いはボットで決める。決めたことと遊ぶ所は、作った後の1枚の表にまとめる。
31. **（企画）手元の段・作る物ごとに「なぜ何度も使うか」「強さのどこを受け持つか」を1行書き、強さの予定表を作ってから作る。**
32. **（オートラン）画面の柱（動く戦いの絵・勇者の欄の位置）をジャンルのお約束に書く。** 最初の試作で、進む速さを2〜3通り遊び比べる。
33. **（画面）動く物と、出たり消えたりする文字を測る。**
    - 動く絵は1枚を動かす。アニメーションはつけ外しせず止めるだけにする。
    - 文字の行は高さを先に取る。
    - 採点は「文字が出た状態」と「動かしている間」も含め、写真だけでなく数秒動かして見る。
    - ゲームの中の言葉は企画のときに一覧にし、仮の開発の言葉を画面に出さない。
34. **（釣り合い）通しのボットを、地域を足すたびに最後まで延ばし、前の地域の終わりから続けて回す。** 手の選び方で数字が動くので、並びや持ち替えはボスと試しに戦って決める。負けた回の削った割合を出して、おかしな所を見つける。

### 頼むときのひな形（今回の分を足した）

```
■目的：何を作る・直すか
■正の文書：企画まとめのリンク（決まったことはここに書き足す）
■変えないこと：遊びの柱、ジャンルのお約束（画面の柱：動く絵・欄の位置も）、固定した数字 など
■ゲームの中の言葉：画面に出す呼び名の一覧（開発の言葉は出さない）
■前提：試すときの条件、遊び方（ふつうの人／工夫する人）、お手本は最初の形か改善した形か
■強さの予定表：地域や段ごとの目安（レベル・装備・技）と、測る道具
■目標：数字と、その測り方（何を相手に、何回測るか。通しのボットは最後まで）
■素材・部品・段の役目：それぞれ「いちばん素直な物ではできないこと」「なぜ何度も使うか」
■大きさの上限：ソルバーやヒントが間に合う範囲
■ルールの当たり前：席の順・最初の先番・同点の扱い
■画面：全ページと切り替えの一覧、出たり消えたりする文字、動く絵。変えたら動かしながら見る
■任せてよいこと：数値の当てはめ、生成、テスト、絵、釣り合い（ボットで）
■必ず確認してほしいこと：遊びの柱にかかわる変更、全体に効く値の変更、2通りに読める指示（「見にくい」は色か形か など）
■人が遊ぶ回数：新しい遊びだけ、全部で○回まで、1回○問
■残っているメモ：Issue 番号（フェーズの終わりに読み上げる）
■報告に入れてほしいこと：足した機能の場所、お手本の前提、画面の確かめ（切り替え・文字が出た状態・動き）、ゲームに出る物か道具だけか、作れなかったもの
■締め切り：日本時間 ○月○日 ○時
■説明：やさしい日本語で、結論から
```
